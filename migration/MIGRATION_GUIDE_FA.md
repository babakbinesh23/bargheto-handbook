# راهنمای انتقال هندبوک برقتو

این بسته، نسخه انتقالی V62 از پروژه «هندبوک برقتو» است. کد منبع از نسخه زنده 61 و داده‌های عمومی در تاریخ 2026-08-02 تهیه شده‌اند.

## داخل بسته چه چیزی وجود دارد؟

- `source/`: کد کامل برنامه، قالب‌ها، APIها، مهاجرت‌های دیتابیس و تصاویر پیش‌فرض.
- `data/content.json`: متن‌های اصلی ذخیره‌شده در دیتابیس.
- `data/customizations.json`: متن‌ها، تصاویر، ترتیب کارت‌ها و تنظیمات ویرایشی فعلی.
- `data/notifications.json`: اعلان‌های قابل دریافت در زمان تهیه نسخه.
- `data/r2/`: تصاویر بارگذاری‌شده‌ای که در داده‌های فعلی به آن‌ها ارجاع شده است.
- `data/seed-d1.sql`: داده اولیه قابل ورود به SQLite/D1، بدون کاربران و نشست‌ها.
- `data/uploads-map.json`: نگاشت آدرس فعلی تصاویر بارگذاری‌شده به فایل داخل بسته.
- `EXPORT_MANIFEST.json`: فهرست دقیق محتویات، نسخه و محدودیت‌های خروجی.
- `SHA256SUMS`: کنترل سلامت فایل‌ها پس از کپی یا آپلود.

## نکته مهم درباره نوع میزبانی

این پروژه یک فایل HTML ثابت نیست. برنامه فعلی به Node.js، اجرای سرور، دیتابیس SQLite سازگار با Cloudflare D1 و فضای فایل سازگار با R2 نیاز دارد. اگر سایت اصلی فقط هاست اشتراکی PHP/cPanel باشد، پروژه بدون بازنویسی بک‌اند روی آن اجرا نمی‌شود.

ساده‌ترین مقصد برای همین کد، Cloudflare Workers به‌همراه D1 و R2 است. روی Vercel یا سرور Node نیز قابل انتقال است، ولی باید لایه `db/index.ts`، آپلود فایل و احراز هویت با سرویس مقصد هماهنگ شود.

## مراحل پیشنهادی انتقال

1. روی مقصد Node.js نسخه `22.13.0` یا جدیدتر نصب کنید.
2. پوشه `source/` را در مخزن مقصد قرار دهید و `npm ci` اجرا کنید.
3. یک دیتابیس D1/SQLite و یک Bucket از نوع R2 بسازید و Bindingهای `DB` و `BUCKET` را تنظیم کنید.
4. فایل‌های `source/drizzle/*.sql` را به‌ترتیب شماره روی دیتابیس اجرا کنید.
5. فایل `data/seed-d1.sql` را اجرا کنید تا محتوای فعلی وارد شود.
6. ساختار `data/r2/` را با همان کلیدها داخل Bucket جدید آپلود کنید.
7. احراز هویت را برای دامنه اصلی تنظیم کنید. منطق فعلی ادمین کل در `source/lib/authorization.ts` و ورود مسئولین در APIهای برنامه قرار دارد.
8. مقدار `OWNER_EMAIL` در `source/lib/authorization.ts` را به حساب مالک نهایی تغییر دهید یا آن را به متغیر محیطی تبدیل کنید.
9. با `npm run build` و سپس `npm test` نسخه مقصد را بررسی کنید.
10. پیش از تغییر DNS، ورود ادمین، ورود یک مسئول، محدودیت واحدها، بارگذاری عکس، ذخیره متن، اعلان و خروج را آزمایش کنید.

## اطلاعاتی که در این خروجی وجود ندارد

خروجی مستقیم دیتابیس مدیریتی توسط سرویس فعلی در دسترس این بسته نبود. به همین دلیل موارد زیر عمداً در ZIP نیستند:

- حساب‌ها و رمزهای هش‌شده مسئولین؛
- جدول مجوزهای کاربران؛
- نشست‌های فعال و کوکی‌های ورود؛
- گزارش کامل رویدادهای مدیریتی.

نشست‌ها و کوکی‌ها اصولاً نباید بین دو دامنه منتقل شوند. برای مسئولین، پس از انتقال حساب‌ها را دوباره بسازید یا پیش از روز مهاجرت از پشتیبانی میزبان فعلی یک Export کامل D1 بگیرید. اگر Export کامل D1 دریافت شد، همان فایل جایگزین `data/seed-d1.sql` می‌شود و مجوزها نیز قابل حفظ خواهند بود.

## ترتیب امن برای روز انتقال

1. ویرایش سایت فعلی را موقتاً متوقف کنید.
2. یک خروجی نهایی D1 و R2 بگیرید.
3. آن خروجی را روی محیط آزمایشی مقصد وارد کنید.
4. ورود و دسترسی یک ادمین و یک مسئول واحد را تست کنید.
5. از دامنه اصلی نسخه پشتیبان بگیرید و سپس DNS یا مسیر سایت را تغییر دهید.
6. پس از تأیید، برای همه مسئولین رمز جدید صادر کنید.

## اجرای محلی

```bash
cd source
npm ci
npm run dev
```

محیط محلی برای توسعه است؛ رفتار هویت ادمین در localhost با محیط نهایی تفاوت دارد و باید پیش از انتشار واقعی بررسی شود.
